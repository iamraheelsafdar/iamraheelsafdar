### How I think about code

I follow a Service-Contract-DTO pattern on the backend. Thin controllers, fat services, interfaces for everything injectable. On the frontend, server components by default, client components only when interactivity requires it. Tests before deploy, lint before commit.

I don't chase trends. If Laravel solves the problem, I use Laravel. If the project needs Node, I use Node. The right tool depends on what you're building, not what's trending on Twitter.
